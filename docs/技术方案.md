# 技术方案：输入栏常驻模型切换器（v1.22）

## 结论

复用现有模型切换全链路（已验证存在且可用），只改 iOS 展示层，一处新增 + 两处版本/测试同步。

## 数据链路（现状，零改动）

```
iOS ComposerView (showReasoning 面板)
  → store.updateSettings(sessionID, model:/reasoning:)   [AppStore]
  → switchModelConfig 命令 (provider/model/thought)       [RelayClient / RelayRemoteTransport]
  → bridge session/setModel 或 relay zcode-session setModel
  → 电脑端 ZCode 生效
模型列表: store.refreshModels() → GET v1/models / relay workspace state → store.models [RemoteModel]
```

## 代码改动点（共 3 个文件 + 1 个测试文件）

1. `ios/ZCodeMobile/Features/ComposerView.swift`
   - `inputSurface` 的 VStack 顶部加一行 `modelChip`：
     `Button { showReasoning = true } label: { HStack { Image("cpu") Text(currentModelName) [Text(思考标签)] chevron } }`
     - 仅当 `!voiceActive && showReasoning == false` 时显示（面板打开时整块输入面板已被替换，无需重复）。
     - `accessibilityIdentifier("composer.modelChip")`，`accessibilityLabel("模型，\(currentModelName)")`。
     - 样式：`.font(.subheadline)` + `.background(.quaternary, in: Capsule())`，tint 走 `ZTheme.accent`。
   - 思考标签：`availableReasoning.isEmpty ? nil : reasoningLabel(currentReasoningValue)`。
   - 不动 `expanded` 逻辑、不动拨盘（拨盘保留在展开态工具条，双入口不冲突）。

2. `ios/project.yml`
   - `MARKETING_VERSION: "1.21"` → `"1.22"`；`CURRENT_PROJECT_VERSION: 21` → `22`。

3. `ios/ZCodeMobileUITests/VerificationFlow.swift`
   - `test04SettingsVersion` 断言 `CONTAINS '1.21'` → `'1.22'`。
   - `test06ChatCompose` 在 tap 输入框之前加两条断言：
     `composer.modelChip` 存在（收起态可见）；点击后 `reasoning.advanced` 出现（面板打开），随后关闭面板继续原流程。

## 兼容性（iOS 16 底线）

- 新增代码仅用 iOS 16 可用 API（Button/HStack/Image(systemName:)/Capsule），不碰 `glassEffect` 原生版，统一走 `compatGlassEffect` 现有扩展（无需新兼容层）。
- Swift 6 + `SWIFT_STRICT_CONCURRENCY: complete`：chip 为纯视图计算属性，不引入新并发状态。

## 构建与交付

- 推送 commit 到 `aksjask/zcode-connect-ios16` main → Actions 自动跑 `build`（出 IPA artifact）+ `screenshots`（模拟器 UI 验证）。
- 用 token 下载 artifact，经 API 创建 Release `v1.22-ios16` 并上传 `ZCodeMobile-ios16-v1.22.ipa`（与既有 v1.17–v1.21 发布方式一致）。
- 用户手机：现有 App 内「IPA 安装器」粘直链或 TrollStore 本地安装。
